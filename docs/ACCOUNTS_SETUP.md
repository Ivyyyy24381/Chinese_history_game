# 账号 · 积分 · 排行榜 — 配置指南 ACCOUNTS_SETUP

## 现在就能用的（无需任何配置）

游戏已内置完整的积分和排行榜功能，**不配置任何东西也能玩**，只是数据存在玩家自己的浏览器里（本地模式）。

### 计分规则（来自建议.docx，改规则编辑 `src/utils/scoring.js`）

| 关卡 | 得分 |
|---|---|
| 选择题（答题/事件问答）| 答对一题 +20 |
| 填诗 | 每空答对 +10 |
| 数字华容道 | 满分 100，每过 1 秒 −1 |
| 出逃 | 满分 50，每过 1 秒 −1，被抓一次额外 −10 |
| 图片找点 | 满分 50，每过 1 秒 −1 |

- 单次游玩每一关只计一次分（重玩同一事件不重复得分）
- 顶栏实时显示本局积分
- 走完人物一生 → 结算总分，自动提交排行榜
- 选人页右上角：登录/注册、🏆 排行榜

## 开启云端账号（邮箱注册 + 全网排行榜）— 腾讯云开发 CloudBase

> ⚠️ LeanCloud 已于 2026 年 1 月停止新注册（2027 年 1 月彻底停服）。本项目已切换到**腾讯云开发 CloudBase**：国内访问快，免费体验环境 3000 资源点/月，以后做微信小程序可无缝衔接（微信登录免注册）。

配置步骤（约 20 分钟，需实名认证）：

1. 打开 <https://tcb.cloud.tencent.com>，用微信/QQ 注册腾讯云账号并完成个人实名认证
2. 创建环境：选**免费体验版**（每账号一个，3000 资源点/月）→ 记下**环境ID**（形如 `xxx-1a2b3c4d`）
3. 左侧「API Key 配置」→ 生成 **Publishable Key**
4. 两个值粘贴进 `src/config/cloudbase.js`：

```js
export const CLOUDBASE_CONFIG = {
  envId: "你的环境ID",
  publishableKey: "你的PublishableKey",
  region: "ap-shanghai",
};
```

5. 「数据库」→ 创建集合 `scores`，权限选**「所有用户可读，仅创建者可读写」**（排行榜大家都能看，分数只能自己提交，防刷榜）
6. 「身份认证」→ 确认已开启：邮箱验证码登录、匿名登录（默认都是开的）
7. 「安全域名」→ 把游戏网址加进去（如 `你的用户名.github.io`），否则浏览器请求会被拒（报 permission_denied）
8. 重新构建部署（`npm run build`），完成

行为说明：

- 注册流程：邮箱+密码 → 收验证码 → 输码完成（CloudBase 强制邮箱验证）
- 未登录玩家也能提交分数和看排行榜（以"匿名玩家"身份、走匿名登录）
- 密钥留空 = 本地模式，一切功能正常，数据只存玩家本机
- 云端逻辑全部在 `src/services/backend.js` 一个文件里，以后要换服务商只改它

> 备选方案：玩家主要在海外可用 Supabase（免费额度大、10 分钟接完，但大陆访问不稳）；想完全自控可自建 PocketBase（单文件后端，需自购服务器+备案）。

### 手机号 / 微信登录（后置）

- **手机号短信登录**：LeanCloud 支持，但短信按条收费，且要申请签名备案。等有推广活动再开。
- **微信登录**：网页版微信登录需要「微信开放平台」企业资质认证（个人不行）。如果以后做微信小游戏，小游戏内是免费自动登录的（见下）。

## 微信小游戏改造评估

结论：**能做，但是一次不小的改造，建议放最后。**

- 微信小游戏**不支持 DOM/HTML**，只有 canvas。本游戏是 React + DOM 写的，不能直接搬进去，UI 层基本要重写（或引入 kbone/Taro 这类适配层，对游戏类支持一般）
- 小游戏也**不允许用 web-view 套壳**（小程序可以，游戏类目不行）
- 上线需要：微信注册小游戏账号、软著或版号相关审核（教育类目相对宽松）、服务器域名备案
- **划算的路径**：先用现在的网页版跑活动（微信里可直接转发网页链接，体验已经不错）；如果验证了需求，再立项小游戏版，届时账号可直接用微信 openid 免注册登录
