## 一、九重天那九条文案 ★ 最想先要你的答案

**问题**：现在写的是「誓愿没能守住的人」「做了好事、但也图个名声的人」
「沉思的人」「推动其余一切的那一重」。10–14 岁读不出画面——这些是分类名，
不是场景。孩子读完不知道那一重天里**有个人正在做什么**。

**已经改好的（不用你管）**：环上不再印 1..9；卡片上不写天名，只留星象符号 +
那句画面；天名点亮之后才在特写里揭晓；加了两个不属于九重天的干扰项。
tray 也真的打乱了（之前是照正确顺序排的，从上往下拖就能通关）。

**要你挑的就是这九句话。** 规矩：≤14 字，要能看见一个人在做一件事。

| 重 | 现在 | 备选 A | 备选 B | 备选 C |
|---|---|---|---|---|
| 月亮天 | 誓愿没能守住的人 | 被哥哥从修道院里抢走的修女 | 她说：在这里我就满足了 | 誓言是别人替她破的 |

| 金星天 | 爱得太多的人 | 爱错过人，死后还在爱 | 情诗写给了不该写的人 | 爱得太满，满出来了 |

## 二、各关收尾那些大段文字 → 「节拍」

**问题**：`coda` / `finale` / `conclusion` 现在是 6–10 行整屏文字。
读到这里玩家已经玩完一关了，注意力最低的时候给最长的一段。

**做法**：做一个可复用组件 `BeatStrip`，把一段话拆成 3–5 个「节拍」，
每拍一个大字或年份 + ≤12 字。

三种排法，挑一个：

**A · 横排时间条**（推荐）
```
  1300 ──────── 1302 ──────── 1315 ──────── 1321
  他签了字      同一套规矩     他拒绝了      他死在
                赶走他        回家的路      拉文纳
```
一屏看完一生的形状。适合 1302、1315、1321 这种「后来怎么了」的收尾。

**B · 竖排落幕**
```
        十四年后
        他把这件事写进了《天堂》第十七歌
        ——
        让 1300 年的先祖，预言 1302 年
        已经发生的事
```
一拍一拍往下落，每拍停 0.6 秒。适合 1292、1300 这种「这段经历变成了什么」的收尾。

**C · 大字 + 一句**
```
        79
        他从佛罗伦萨带走的全部
```
最省字，最重。适合 flee_florence 那种已经很短的关。

**要你定的**：三种都做，还是只做一种？我的意见是 **A + C 两种就够**，
B 其实是 `RevealLines` 已经在做的事（逐句显影），再做一个是重复。

`BioPanel` 的生平段落同理：改成年份点的时间条，长文收进「详细」折叠。
这个不用你定，A 定了我就照做。

## 三、`explore` —— 全线最多的一类，仍然是「点人读字」

全线 125 幕里 `explore` 占 27 幕（22%），是单一类型里最多的。
lint 把它归在「浏览」——找一找，读一段——不计入认知动作占比。

三条路，从便宜到贵：

**A · 只加动效（便宜，今晚就能做）**
NPC 进场时从下方浮起、错峰 80ms；点过的立绘降饱和 + 名牌打勾；
未点过的轻微呼吸。**不改内容，不改字数，不改 lint 数字。**

**B · 给 explore 加一个「收口」（中等）**
逛完之后不是直接「继续」，而是先问一句需要判断的话，
再进下一幕。等于把每个 explore 末尾接一个微型 `predict_reveal`。
→ 认知动作占比会真的涨；但每个 explore 要多写一道题（约 40 字 × 27 幕）。

**C · 把 explore 改成「找证据」（贵）**
场上放 5 个人，题面先给一个判断，玩家只点「支持这个判断的那几个」。
→ 这就是 `evidence_select`，只是搬进了场景里。改造成本最高，
但它把「浏览」变成「辨证据」，是唯一能真正把占比推上 40% 的路。

**我的推荐**：**A 现在就做**（纯视觉，零风险），
**C 挑两三个事件试点**（1295 医药行会大厅、755 长安街头这种人多的场景最合适），
成了再铺开。B 不推荐——它是在 explore 后面打补丁，没解决 explore 本身。

## 四、放逐循环「满城那一幕」的视觉

**问题**：现在是一张纯柱状图 + 两个滑块，很像仪表盘。
这一关讲的是「一座城在换人」，但看起来是「一张图在动」。

**不能动的**：图表配色顺序（相邻对的色觉分辨度按那个序验过，
我试过按游戏配色重排，CVD ΔE 掉到 4.8，直接 FAIL）。

**三个方案**：

**A · 城里站着 30 个小人**（Ivy 原话的直译）
六种人各五个，用 `icons.js` 的 SVG 小人，按策略上色（沿用那六个色）。
每一代结束，垫底的五个淡出、换成头五个的颜色淡入。
柱状图缩到右下角当辅助。
→ 最像「一座城在换人」。成本：一个 30 格的网格 + 淡入淡出，纯 CSS。

**B · 城墙里的人口条**
画一段城墙剖面，六种颜色像地层一样堆在里面，每一代地层厚度变化。
→ 比柱状图更像「城」，但比 A 抽象。成本最低。

**C · 一张脸的网格**
30 个头像框，用现有立绘的裁切（科尔索、福雷塞、圭多…）循环填充。
→ 最有情感，但会误导：这些人不是那六种策略的代表。**不推荐。**

**我的推荐 A**。另外建议加一条：**每一代结束时，把「城的元气」那条血条
的变化画成一次抖动**——现在血条在掉，但没人注意到它在掉。

## 五、`forced_choice` 的图片选项（1.5 只做了一半，需要你定方向）

全线还有 **12 个纯文字的 `forced_choice`**（但丁 6、杜甫 6，共约 30 个选项）。

**卡在哪**：`predict_reveal` 的 `option.image` 和 `mode:"gates"` 两条路
**都需要图片文件**，而铁律 4 说不生成图片。1302 和 1315 能用是因为它们
已经有 choices/*.webp。

**两条不用出图的路**：

**A · 用 `icons.js` 的 SVG 图标当选项卡**（推荐）
给 `forced_choice` 和 `predict_reveal` 都加 `option.icon`，
渲染成「大图标 + ≤8 字标题 + 小字正文」的卡片。
图标从 game-icons.net 取 path 粘进 `icons.js`，一个约 1KB，随 CSS 改色。
现在库里只有 7 个（codex / manuscript / florin / letters / cloak / spindle / gate），
30 个选项大概要再取 20 个。
→ **机制我可以直接做**；但「哪个选项配哪个图标」是审美，30 个我先出一版，
你逐个改。

**B · 纯 CSS 画的抽象卡**
两扇门 / 一条岔路 / 一只手按在纸上——用 CSS 渐变和形状画。
→ 完全不依赖图标库，但每个选项要单独设计，工作量比 A 大得多，
而且风格容易和全站楷体纸面打架。

**我的推荐 A**，并且建议**先只做但丁线那 6 个**，看顺眼了再铺杜甫线。

顺带一个要你定的内容问题：这 12 个 `forced_choice` 里，
有几个其实是**伪选择**（选哪个剧情都一样往下走）。
`DESIGN_VERBS.md` 里你自己写过「predict_reveal 替换：大量作为伪选择的
forced_choice」。要不要我逐个标出来，你再决定哪些改成 `predict_reveal`？
改了认知动作占比会涨（forced_choice 和 predict_reveal 都算「先判断」，
但 predict_reveal 不打对错，教学上更干净）。

### `770_xiangjiang` —— `··○···`（H1 连续 3 个读屏 + H2）

六幕：出夔州后（过场）→ 岳阳楼（连环画）→ 漂泊路线（地图）→ 回忆（连环画）→

> 题面：五十九岁，船困在耒阳，江水暴涨，五天没吃上东西。
>      县令送来酒肉。
> 问：后来传说他是怎么死的？

## 八、逐幕审查翻出来的、要你拍板的几件（完整清单在 `docs/AUDIT.md`）

### 1. ★ 石壕村排序的「正确顺序」可能是错的 —— 这条最急

`comic_sort` 现在认定的顺序，是照那张长图上原本烧死的说明带编号来的：

```
1 杜甫伏案写字 → 2 老翁翻墙 → 3 老妇开门 → 4 巷口火把亮起 → 5 挨家敲门 → 6 杜甫紧闭窗棂
```

但《石壕吏》原诗是：

> 暮投石壕村，**有吏夜捉人**。**老翁逾墙走**，老妇出门看。吏呼一何怒……

诗里**吏先来，老翁才翻墙**。按诗，顺序应该是：

```
1 写字 → 4 火把亮起（吏到） → 2 翻墙 → 3 开门 → 5 敲门盘问 → 6 听着
```

也就是说**画师给这张图编的号和诗对不上**。对一个排序游戏来说这是致命的：
玩家如果按诗推理，会被判成排错。

三条路，要你选：
- **A** 按诗改 `panels` 的顺序（我推荐）。画面上「火把在巷口」和「翻墙」谁先谁后
  看不出来，但诗说得很清楚，而这一关本来就该教「读诗」。
- **B** 保持画师的顺序，但在题面上加一句限定（「按画上的先后」）——弱，
  等于承认这张图和诗不一致。
- **C** 换掉 p4/p5 两格，只留能凭画面判断先后的四格。最保守，但丢掉两格好画。

**在你定之前，这一关是可疑的。** 我没有自己改，因为「以画为准还是以诗为准」
是内容判断。

### 2. `forced_choice` 是一台 ✓✗ 机器（全线 12 处）

现在的行为：选错 → 弹黄框、选项不消失、**没有「继续」**，必须回头点中
`correct: true` 的那个才放行；选对 → 弹绿框。对错**只靠颜色承载**（绿 `#D4EDDA`
/ 黄 `#FFF3CD`），色觉障碍玩家读不出来。而且只有第一次就答对才计分。

这**直接违反** `DESIGN_VERBS.md` 的第 2 条推论（「不打 ✓✗，玩家的答案要留在
屏幕上，和正确答案并列」）。而且好几处的「错」选项根本不成立
（1283 的「忘记她」、744 的「默默走开」、747 的「运气不好」），是伪选择。

**我建议**：把 `forced_choice` 整个改成 `predict_reveal` 的行为——
选了就走，把「你选的 / 他做的」并列留在屏上，不拦不判。
但这会改动 12 处的手感，所以等你点头。

### 3. quiz 的答案被原文印在紧挨着的幕里（至少 5 个事件）

1265、1283、1295、1321、765_kuizhou 都有：quiz 的答案原句就在前一两幕的
台词或注疏里逐字出现过。玩家不是在回忆，是在抄。
要改的是 quiz 的问法（往推理上问），不是删材料——这是内容活。

### 4. 三处地图站点画错了地方

- `1302_esilio p3` 归途三站全在错的地理位置，「佛罗伦萨地界」画在意大利靴尖的

### 6. `comic_sort` 和 `comic_reveal` 挨在一起，第二幕在重复第一幕

我把 `comic_sort` 排在 `comic_reveal` **之前**（先自己排，再逐格读），
但两幕用的是同一张图、同一组格子——玩家刚亲手排完，下一幕又把它们重新盖黑、
一格一格揭开。审查里说得对：「遮挡这个机制在这里已经没有对象了」。

三条路：
- **A** 保持现状。理由是这正是 `Do first → see consequence`：先凭画面排出顺序，
  再听每一格里的人到底说了什么。重复的是画面，不重复的是台词。
- **B** 当同一事件里 `comic_sort` 在前时，`comic_reveal` 不再盖黑，改成
  「全部可见 + 逐格点亮」。改动小，我可以做。**我倾向这个。**
- **C** 两幕合成一个：排完顺序后直接在原地逐格出台词，省掉一整幕。
  最干净，但要重写 `comic_sort` 的收尾。

（1265 和 759 两关都是这个情况。）
